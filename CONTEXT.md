# GIDC systems: how they work and why

Written 23 October 2026. This is the file to read first.

The code in this archive is the easy half. This document is the half that
is normally lost: what the pieces are, what was decided and why, and the
specific facts about Grinyer's own data that took weeks to find out and
that nothing in the code explains.

If you are picking this up cold, read this end to end before changing
anything.

---

## 1. What exists

Five separate things, sharing one set of logins.

**The dealer portal**, `dealers.gidc.ca`. One self contained HTML page,
about 430 KB of source, built by `build.py` into `index.html` and
uploaded to Cloudflare Pages. Dealers place and track door orders here.
Grinyer staff use it too, acting as Grinyer's own dealer record, which is
how the office places an order the same way a dealer does. Version 1.99
as of 19 October. There is no server: the page talks to Supabase
directly, and the database rules are the only thing enforcing anything.

**The tools site**, `tools.gidc.ca`. One Cloudflare Pages project serving
a landing page and ten tools from folders beside it. Cloudflare Access
sits in front of it and is what actually refuses to serve the page; the
sign in inside it keeps things tidy but is not a lock. Tools 2.9 as of 20
October. Contains the company dashboard, daily production, go backs, the
estimate and invoice tools, the Proliner analysis, the packing sequencer
and the export documents builder.

**The measurement app**, `measurement.gidc.ca`. Deployed separately and
deliberately: sales reps have it installed on their phones and are signed
in, and moving it would break both. Version 1.9. **The live file is
`deploy/index.html`, not `app.html`** — `app.html` is stale and missing
about twelve functions. This nearly caused a bad mistake on 19 October.

**The office server**, `SVR-GDDC`. Runs PowerShell against the Access back
end at `\\SVR-GDDC\GIDC Database\Grinyer_be.accdb`, hourly, pushing
numbers into the dashboard through a Supabase edge function. The scripts
are in `powershell/`.

**The Google Sheet**, which the website contact form writes to. An Apps
Script in it counts submissions per day and posts them to the same edge
function. In `apps-script/`.

- `KPI_IMPORT_KEY` in Supabase secrets, matched by `GIDC_KPI_KEY`

- `RESEND_API_KEY` in Supabase secrets. Sends order emails and go back

### Edge functions

| name | what it does | needs |
|---|---|---|
| `create-dealer-user` | makes, edits, repasswords and removes logins | service role |
| `kpi-import` | the only door numbers come in through | `KPI_IMPORT_KEY` |
| `send-goback` | emails a go back to the office | `RESEND_API_KEY` |
| `send-order-function` | emails a dealer order | `RESEND_API_KEY` |

`kpi-import` writes all rows or none. One bad row rejects the batch with
a sentence naming which. That is deliberate: a half imported night is
worse than one that did not run.

### How access is decided

Every rule in the database compares `dealer_id` against `my_dealer()`, or
calls a helper. **Not one policy reads the role column directly.** That is
why the two sided access change came out small, and it is a property
worth preserving: put new logic in a helper, not in a policy.

The helpers are all written as lists of who **may**, never lists of who
may not. A denylist admits every role invented afterwards because nobody
goes back to add it to the exception. Two of them were denylists and both
caused real holes.

## 3. Decisions, and the reasoning

**Roles are an allowlist, everywhere.** Said twice above because it is the
single most important convention here. `can_see_prices()` and
`can_order()` were both written as "anybody who is not a dealer
administrator" and both let in every account with no role at all.

**A new account gets nothing.** Until 21 October the trigger that makes a
profile gave every new account role `user`, which is full staff including
the wholesale price list. Self signup is enabled on the project because
the measurement app depends on it. Fixed in `sql/security-tighten.sql`.

**Nobody chooses anybody else's password.** Decided 21 October. New people
get an invitation link and set their own, which verifies the address in
the same act. Replaces the old flow where an administrator picked a
password and handed it over.

**Verification has its own record, not Supabase's flag.** Every existing
login was created with `email_confirm: true`, so Supabase believes all
nineteen addresses are verified. That belief records a box being ticked,
not anybody proving they can read the mailbox. Hence
`profiles.email_verified_at`, set only by following a link.

**A level is drawn as a line, a flow as bars.** On the dashboard, a metric
with `kind = 'level'` is a reading of a moment, so it gets a line that
does not start at zero, because 39 against 43 drawn from zero is a flat
line. A flow is accumulated over the bucket, so it gets a bar measured
from zero. A missing day breaks the line rather than being interpolated.

**A missing day is not a zero.** Applies everywhere. The Google Sheet
script sends an explicit zero for a quiet day, because a quiet day is a
fact. `DailyLog_EstimateStatus` skips days the office machine did not
run, and those are left absent, because nobody wrote them down.

**Explicit access beats a fallback.** A staff login with no dealer of its
own acts for Grinyer's record. One that has been given real dealer access
acts for that dealer instead.

## 4. Facts about Grinyer's data that nothing explains

These cost the most to find and are invisible in the code.

**`OrderNo` is not `OrderID`.** They sit two apart in this data. Aris is
OrderNo 5067 and OrderID 5069; Cortes 4273 and 4275. `access_order_id`
stores the **ID**. Getting this wrong links an order to the wrong job.

**`access_order_no` holds the No, `access_order_id` the ID.** Added 23
October with `sql/dealer-order-number.sql`. People type the No, the job
number on the Access screen; the database finds the ID from the staged
Access rows and the sync follows the ID. See `docs/dealer-sync.md`.

**Style names do not match between the price list and what dealers type.**
The list says "Clear 1-Lite", dealers type "Clear 1 Lite". The portal
normalises with `pnorm`, lowercase with every non alphanumeric stripped.
The database equivalent is `gidc_pnorm()`. A screen priced 359.31 while
the database said 0 until these agreed. 2304 combinations verified.

**Dealer short names are capitals since 15 October.** `SOUTHFLORIDA`, not
`southflorida`. Anything comparing a short name must do it with the case
and punctuation taken out. A letter for letter comparison in
`my_dealer()` shut every staff login out of the portal four days later,
and the error it produced said the record was missing when it was not.

**`DailyLog_EstimateStatus` holds the history of the booked figures.** One
row per day since 18 September 2018, with a column per estimate status
named after the status number. Column 1 is Initial Visit Booked, column 4
is Showroom Booked. Fourteen of sixteen columns agree exactly with a live
count. **Columns 7 and 9 are out by 654 and 11 and nobody knows why.**
Whatever writes that log excludes something. Do not use those two columns
until that is understood.

**`DailyLog_OrderStatus` has `InstallBacklog`** going back to 2018, which
looks like the installation backlog in days. Never verified against a
live count, so never imported.

**`def_Employees` stores staff passwords as readable text.** Treat every
one of them as known.

**Proliner files.** `applyMeasurements` matches swing rows by opening
number first, then positionally. The positional fallback is disabled when
the file is numbered and any line matched by number, because without that
a pocket door's measurement was silently given to a single swing on the
DISANTI order. Still open: whether the measurer numbers to match the
contract's opening numbers or counts sequentially over what they
measured. The DISANTI widths fit the sequential reading perfectly.

**Astragals.** A double swing dummy gets none. A double swing gets an
astragal. A double swing with a value above zero in the astragal field
gets a T astragal. Doors with no price in the hollow section of the list
only come in solid and are not charged for re railing.

**PostgREST quirks.** A PATCH matching zero rows returns 200 with `[]`,
not an error, which hid two silent failures. An RPC without
`headers(true)` resolves to a zero argument function and 404s. Run
`notify pgrst, 'reload schema'` after any DDL.

## 6. Conventions

- Written output for Andrew contains no hyphens or dashes of any kind.
  Rewrite the sentence instead.
- Explorer scripts print shapes, counts and dates only. They carry a
  `$HIDE` pattern and never print a name, address, phone number, price or
  commission. Read only, `Mode=Read`, and they say so.
- Every SQL file is safe to run twice and says so at the top.
- SQL files are written to be the whole truth about the thing they
  change, restating rules they depend on, because these files are a
  history of patches and whichever ran last is what is live.
- Tests go in both directions: that the thing now works, and that
  everybody who had access yesterday still has exactly what they had.
